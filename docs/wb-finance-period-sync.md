# Сбор финансовых отчётов WB за период

`finance-collector sync-reports-wb` читает официальный список до HTTP 204,
затем детализацию каждого найденного закрытого отчёта до отдельного HTTP 204,
выполняет существующую сверку и публикует результат в PostgreSQL.

Пример для серверного оператора; пути и ID берутся из реестра развёртывания:

```sh
finance-collector sync-reports-wb \
  --registry /etc/mcp/access.json \
  --actor finance_operator --account wb_account \
  --credentials-dir /run/marketplace-credentials \
  --state-dir /var/lib/mcp/finance \
  --from 2026-08-01 --to 2026-08-31 \
  --observation august_review_01 --period weekly \
  --follow true --max-run-seconds 3600
```

Нужен `REPORT_COLLECTOR_DATABASE_URL` с ролью `report_collector`; ключи и
строка подключения не передаются аргументами команды. По умолчанию действует
`collector-proxy`. Состояние хранится в одном постоянном приватном каталоге,
общем для запусков по этому продавцу.

## Продолжение после остановки

Без `--follow true` команда работает до сохранённой отсрочки. С этим флагом
процесс сам продолжает страницы после пауз, не дольше указанного времени:
1–86400 секунд, по умолчанию час. Бюджет охватывает активный вызов и ожидание.
Его исчерпание возвращает `collection_paused`, `collection_complete=false`
и `resume_same_observation=true`.

Для продолжения после перезапуска повторяется команда с теми же периодом,
`observation` и каталогом состояния. Страницы читаются из журнала; уже готовые
отчёты проходят идемпотентную публикацию без дублей. Локальный флаг «готово»
не заменяет проверку БД.

Новое независимое наблюдение получает новый `observation`. Изменённый отчёт
с тем же ID вызывает существующий `RevisionConflict`: исторические публикации
автоматически не перезаписываются.

Продолжаются только штатные отсрочки и ограничения запросов. Ошибки прав,
структуры, БД и конфликты публикаций завершают процесс ошибкой. На каждом
обращении и перед публикацией заново проверяются оператор, роль, кабинет
и привязка ключа. Ожидание не удерживает файловую блокировку продавца;
квота сохраняется на диске.

## Готовность и сверка

Пределы: закрытый интервал до 31 дня и до 256 отчётов. Валюта каждого отчёта
сохраняется отдельно. `--currency` и `--report-id` в этом режиме не принимаются.

- `deferred` содержит число уже опубликованных и всех найденных отчётов.
- `reports_published_complete` означает завершение всех найденных публикаций;
  у каждого отчёта остаётся отдельный результат сверки.
- `no_reports` означает пустой завершённый список, а не нулевой финансовый результат.

Применяется действующий контракт двух итогов WB: `retailAmountSum` и `forPaySum`.
Статусы `mismatch` и `unavailable` сохраняются. Дневные отчёты можно собирать,
но недельные формулы не объявляются проверенными для дневных. Банковская
выплата, прибыль и формулы остальных удержаний этой командой не подтверждаются.
`profit` остаётся `null`; интеграция с 1С не включена.

Публикации читает существующий
[`ofk_wb_report_reconciliation`](wb-report-mcp.md). Ключи остаются у сборщика.
Установка бинарника не включает расписание и не меняет рабочие сервисы.
Серверный планировщик может повторять согласованные период и наблюдение
до завершения, затем создавать следующее наблюдение.
