# Восстановление «Одуванчика» без повтора неоднозначной записи

Миграция `031_wb_audited_incident_recovery.sql` добавляет административную
операцию `wb_automation.recover_oduvanchik_unconfirmed_bid`. Автоматический
writer не получает прав на неё. Это не прямой сброс `incident_class` и не
повтор рекламного запроса. Применение миграции само по себе ничего не
разблокирует. Не применять SQL отдельно от штатного обновления образа БД:
журнал миграций и проверки здоровья должны соответствовать установленному образу.

## Предусловия

- Явное разрешение пользователя сохранить текущие ставки, закрыть конкретный
  неподтверждённый запрос и восстановить управление.
- Только `ofk_region_wb` / `39807762`; `change_bids` в
  `reconciliation_required`, инцидент `write_result_ambiguous` либо
  `write_not_reconciled`. Остановки по лимитам не снимаются.
- Проверенный выпуск БД, резервная копия и тесты на отдельной PostgreSQL.
- Независимая свежая сверка WB: status 9, точные пять товаров и ставки.
- Записанный циклом робота снимок той же ревизии/политики не старше 90 секунд,
  положительный бюджет, полный дневной расход ниже 450 ₽. Повышение из старого
  запроса не должно быть видно в снимке: если видно, нужен обычный reconcile.

## Выполнение

Администратор передаёт шесть типизированных параметров (без подстановки
секретов в SQL): старый idempotency key, ожидаемую ревизию состояния,
policy digest, ID свежего цикла, JSON текущих ставок и reference разрешения.

```sql
SELECT wb_automation.recover_oduvanchik_unconfirmed_bid(
    $1, $2, $3, $4, $5::jsonb, $6
);
```

Функция берёт тот же advisory lock, что робот, и блокировку строки состояния.
В одной транзакции записывается append-only аудит, попытка закрывается как
`cancelled` с причиной `operator_closed_unconfirmed` **с сохранением исходного
времени отправки и тела запроса**, снимается только связанный incident/pending,
ревизия увеличивается, время последнего действия устанавливается в момент
восстановления для штатной выдержки паузы перед следующими действиями.
Счётчик действий не уменьшается внутри того же торгового дня. Политика,
бюджет, ставки и protective pause не изменяются. Результат старого запроса
остаётся неизвестным, а не помечается `applied`.

Ключ старой попытки навсегда остаётся занят. Повтор функции с прежней ревизией
не допускается. После таймаута сначала читать состояние, attempt и audit;
не повторять вызов вслепую. Новая рекомендация на ту же числовую ставку в
будущем допустима только как новое решение по свежим данным и ограничениям.

## Проверка результата

Перечитать независимые WB details (состав/ставки/status), состояние БД,
закрытую попытку и событие `operator_closed_unconfirmed`. Затем дождаться
планового цикла и проверить его фактический outcome. Нельзя считать завершение
миграции, административный ответ либо healthy контейнер доказательством работы
робота. Никакого пополнения, ручного повышения или запуска других кампаний.
