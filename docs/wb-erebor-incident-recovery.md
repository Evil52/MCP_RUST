# Восстановление неподтверждённой ставки Эребора

Миграция 047 добавляет административную функцию
`wb_automation.recover_erebor_unconfirmed_bid` только для
`ip_usovik_wb` / `40508432`. Она сохраняет текущие ставки и закрывает
конкретный старый запрос как `cancelled` с аудиторской причиной
`operator_closed_unconfirmed`. Результат старого запроса остаётся неизвестным;
его idempotency key и исходное тело сохраняются навсегда.

Перед восстановлением нужны разрешение пользователя восстановить управление
с сохранением текущих ставок, резервная копия, проверенный выпуск БД и
независимое свежее чтение WB. Функция требует последний цикл робота не старше
90 секунд, ту же ревизию и политику, пять точных SKU, активный статус 9,
положительный бюджет, полный дневной расход ниже 450 ₽ и отсутствие защитной
паузы. Если целевая ставка старого запроса видна в WB, требуется обычный
reconcile. Старый запрос не отправляется повторно.

```sql
SELECT wb_automation.recover_erebor_unconfirmed_bid(
    $1, $2, $3, $4, $5::jsonb, $6
);
```

Параметры: ключ попытки, ожидаемая ревизия, digest политики, ID свежего цикла,
JSON текущих ставок, ссылка на разрешение пользователя. После вызова проверить
attempt, execution_state, append-only audit и независимый readback WB, затем
первый штатный цикл. Квоты, пределы расходов и политика не меняются; после
восстановления действует обычная пауза перед следующей корректировкой.

Для чтения ставок ниже нижней границы политики нужен образ `wb-automation`
не старше релиза `9cd5a79`. Старый образ `b251556` отклоняет такое наблюдение
целиком и не сохраняет свежий цикл для восстановления. Проверять фактический
образ планового worker, а не только образ MCP-сервера.

При новой ошибке записи worker выводит очищенное событие `wb_write_failed`
в stderr: класс ошибки, HTTP-статус и безопасный request ID. Токены, URL,
тела запросов и ответы WB туда не попадают. Ошибка по-прежнему блокирует
повторные записи до reconciliation.
