# Подключение нового компьютера к Ubuntu

Администратор передаёт сотруднику адрес сервера, серверный логин и проверенный
отпечаток SSH host key по доверенному каналу. Сотрудник сохраняет приватный
ключ на своём компьютере и передаёт администратору только файл `.pub`.

## Подготовка SSH

На Linux или macOS проверьте наличие OpenSSH client. Новый ключ создаётся
только при отсутствии подходящего существующего ключа:

```sh
mkdir -p ~/.ssh
chmod 700 ~/.ssh
ssh-keygen -t ed25519 -a 64 -f ~/.ssh/mcp_ubuntu_ed25519 -C mcp-employee
```

Задайте passphrase. Не перезаписывайте существующий файл ключа. Для уже
созданного RSA-ключа используйте его фактическое имя; новый ключ для этой
процедуры не обязателен. Отпечаток публичного ключа можно проверить локально:

```sh
ssh-keygen -lf ~/.ssh/mcp_ubuntu_ed25519.pub -E sha256
```

## Добавление ключа на сервер

Администратор использует уже работающий SSH или консоль VM. Перед изменением
нужно определить целевой серверный аккаунт. Ключ существующего аккаунта
предоставляет полномочия именно этого аккаунта, включая имеющееся sudo.
Отдельному сотруднику предпочтителен отдельный аккаунт с необходимыми правами.

Следующие команды выполняются **от имени целевого пользователя на сервере**:

```sh
id -un
mkdir -p ~/.ssh
chmod 700 ~/.ssh
touch ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
nano ~/.ssh/authorized_keys
```

Добавьте публичный ключ одной строкой в конец файла. Сохраните все
существующие ключи, включая завершающий перевод строки. Ссылка `mailto:` или
Markdown-разметка не являются частью ключа; комментарий после Base64 обычный
текст. Файл и каталог должны принадлежать целевому пользователю.

Добавление ключа не требует перезапуска SSH или включения парольного входа.
Не закрывайте текущую административную сессию до проверки нового входа.

## Проверка входа

Получите фактический адрес, логин и отпечаток сервера из закрытой описи.
При первом подключении сверяйте host key с доверенным отпечатком; не
отключайте его проверку. Проверяйте вход из нового терминала сотрудника:

```sh
ssh -o IdentitiesOnly=yes -i ~/.ssh/mcp_ubuntu_ed25519 SERVER_LOGIN@SERVER_HOST
```

Замените `SERVER_LOGIN`, `SERVER_HOST` и путь ключа. После входа выполните
`id -un` и `hostname`, чтобы убедиться в выбранном аккаунте и сервере.
При timeout сначала проверьте сетевой путь. Ключ сам по себе не исправляет
маршрутизацию или запрет TCP/22; широкие разрешения для офисной сети не нужны.

## VS Code Remote SSH

Установите расширение Remote - SSH издателя Microsoft. Создайте локальный
alias с согласованными HostName, User и IdentityFile, подключитесь через
Remote-SSH и откройте отдельную рабочую копию проекта. Проверьте место запуска
расширения агента и его действительные права. SSH не требует выдачи Docker
socket, доступа к production secrets или административного sudo.

После приёмки администратор отзывает старые ключи отдельно, сохраняя
подтверждённый доступ преемника и аварийный вход.
