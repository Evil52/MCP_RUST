# Чтение сверки официального отчёта WB

`ofk_wb_report_reconciliation` читает опубликованный в PostgreSQL отчёт по
разрешённому кабинету. Инструмент доступен Finance и Admin; сервер заново
проверяет сотрудника, его роль и кабинет при каждом запросе страницы.
Запрос не обращается к WB и не использует ключи маркетплейса.

Параметры:

- `account_id` — обязательный канонический кабинет WB из реестра доступа.
- `report_id` — обязательный положительный int64 ID **строкой**.
- `after_rrd_id` — необязательный точный строковый курсор из предыдущего ответа.
- `limit` — от 1 до 1 000 строк; по умолчанию 100.

Неизвестные поля запрещены. Для продолжения страницы нужно повторять тот же
`account_id` и `report_id`. Числовая JSON-запись больших ID не принимается,
поскольку JavaScript может потерять разряды ещё до запроса.

Если опубликованного отчёта нет, ответ содержит `state: "N/D"`, `report: null`
и `comparison: null`. Полностью собранный и опубликованный отчёт имеет
`state: "COMPLETE"`. Это подтверждает сбор до HTTP 204, включая все страницы,
а результат финансовой сверки передаётся отдельно:

- `primary_totals_match` — совпали два основных итога: `retailAmountSum` и
  `forPaySum`. Это не подтверждение банковской выплаты или прибыли.
- `mismatch` — хотя бы один основной итог отличается; передаётся точная разница.
- `unavailable` — для сопоставления не хватает данных либо нет подтверждённого
  правила; `unavailable_reason` сохраняет конкретную причину.

Сводная сверка остаётся одинаковой на всех страницах одного опубликованного
отчёта. Она не пересчитывается из текущего среза строк. При чтении всего отчёта
одной страницей MCP дополнительно проверяет сохранённые итоги по строкам.
Различная точность источника и PostgreSQL сравнивается точно, без округления.

Денежные значения передаются как `{ "units": "...", "scale": 16 }`: коэффициент
является строкой, фактическое значение равно `units / 10^scale`. Сохраняется до
18 десятичных знаков, включая обнаруженную у WB комиссию `vw` с 16 знаками.
Перекрывающиеся денежные колонки не складываются в искусственную прибыль.
Названия документов и операций остаются недоверенными данными.

В происхождении данных доступны период, валюта, число строк, ID снимка,
хеши независимых сводки и детализации, хеш публикации и время публикации.
Доступ к готовой публикации не заменяет авторизацию сотрудника.
