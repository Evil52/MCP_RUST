# История остатков на складах продавца WB

Фоновое задание Stocks теперь собирает остатки на складах WB и на всех
складах продавца. Только завершение обеих частей разрешает публикацию общего
снимка. История начинается с фактического времени сбора: старые снимки FBW
не становятся историей FBS, а текущий снимок не заменяет остаток на конец августа.

## Источники и охват

[Официальная инструкция WB](https://dev.wildberries.ru/en/news/101) задаёт
связку списка складов, карточек и остатков по ID размеров. Сборщик использует:

- `GET /api/v3/warehouses` — все склады продавца с типом доставки.
- `POST /content/v2/get/cards/list` — карточки вне корзины по 100 записей,
  с курсором `updatedAt + nmID`, до страницы короче лимита.
- `POST /api/v3/stocks/{warehouseId}` — остатки по `chrtIds`, пакетами до 1000.

[Контракт WB](https://dev.wildberries.ru/openapi/work-with-products)
описывает эти операции чтения. Для них нужен фактический доступ ключа к
Content и Marketplace; наличие Finance или Analytics его не подтверждает.

Сохраняется соответствие `chrtID → nmID`. Размеры суммируются внутри SKU
отдельно для каждого склада. Проверяется уникальность карточек и размеров.
Временные страницы содержат только ID, количества и курсоры: описания,
названия и ссылки из ответов не сохраняются.

Пространства имён `warehouse_id` разделены:

- `wb:123` — существующий склад WB.
- `wb:seller:1:123` — склад продавца с `deliveryType=1`, FBS.
- `wb:seller:2:123` — склад другого типа доставки, сохранённого как значение WB.

Одинаковые числовые ID не объединяют эти склады. Другие положительные типы
доставки сохраняются явно и не переименовываются в FBS.

## Неполные данные

Если WB не вернул запрошенный размер, результат получает
`seller_stock_coverage_incomplete`. Пропущенный размер не считается нулём.
Явный `amount=0` принимается. Чужие ID, повторы, отрицательные количества,
сломанный курсор и переполнение отвергаются.

Пределы: 100 складов, 25 000 размеров, 25 000 строк общего снимка. Превышение
не обрезает данные: публикация завершается ошибкой. Пустой список складов —
наблюдаемое отсутствие складов; ошибка доступа не превращается в пустой список.

При недоступном FBS новый общий снимок Stocks не публикуется как полный;
предыдущие снимки сохраняются. Отдельная публикация свежего FBW при недоступном
FBS потребовала бы отдельного контракта готовности частей Stocks.

## Продолжение сбора

Страницы сохраняются в PostgreSQL с одной арендой и одним новым HTTP-запросом
за квант работы. Миграция **037** разделяет сохранённые ограничения Analytics,
Content и Seller Inventory. Для последних двух используется консервативная
пауза две секунды. `Retry-After` продлевает ограничение именно вызванной группы.

Альтернативная группа разрешена функцией БД только для задания Stocks WB.
Продажи не могут использовать её для обхода своих пауз. Потерянная аренда
не допускает запрос. Общий срок задания и предел 30 минут между наблюдениями
остатков сохранены. При выпуске сначала останавливается прежний сборщик,
затем применяются миграции 036–037 и запускается обновлённый процесс.
Старый процесс не должен параллельно публиковать снимки только FBW.

Синтетические тесты проверяют продолжение страниц, охват размеров, разные
модели доставки, квоты, роли и публикацию в реальной временной PostgreSQL.
Фактические права и охват каждого рабочего кабинета проверяются после выпуска
по результатам плановых заданий.
