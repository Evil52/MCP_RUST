# Сохранённая квота WB Finance

Finance-методы используют одну локальную очередь по проверенному SID
продавца. Отдельные методы и псевдонимы кабинета не создают независимые
лимиты. Перед HTTP резерв синхронно сохраняется на диск. Процесс держит
эксклюзивную блокировку до завершения запуска.

Локальные признаки Personal/RO/Finance недостаточны для ускорения:
сначала требуется успешный HTTP 200 или 204 финансового метода с этим
ключом. Только после этого интервал 60 секунд сохраняется вместе с SHA-256
ключа. Сам токен и SID в файле квоты отсутствуют. Неудача или падение до
сохранения подтверждения оставляет консервативный резерв 12 часов.

Ответ `Retry-After` сохраняется отдельным сроком. Успешное чтение,
перезапуск, другой метод и смена ключа не сокращают этот срок. Доказательство
для старого отпечатка не ускоряет новый ключ. Все последующие вызовы снова
проверяют действующую роль оператора, разрешённый кабинет, SID и срок ключа.

[Документация WB Finance](https://dev.wildberries.cn/docs/openapi/documents-and-accounting)
указана в [контракте методов](wb-financial-details-contract.md). Она не
гарантирует отдельные пулы ограничений для каждого нового метода. Локальная
квота действует только для одного хоста и общего постоянного каталога.

## Переход старой успешной пробы

В первоначальном журнале сохранялся только `next_allowed_at`. Такой срок
нельзя автоматически объявлять обычным интервалом: он мог происходить от
ограничения поставщика. По умолчанию он сохраняется без изменений.

Для известной успешной пробы доверенный оператор ОС может подготовить
приватную квитанцию `legacy-success-receipt.json` рядом с `quota.json` и
выполнить явную команду `migrate-personal-quota` с теми же аргументами
реестра, оператора, кабинета, каталога ключей и состояния. Команда не
обращается к WB и не принимает ключ в аргументах.

Проверяется версия квитанции 1, точное совпадение оператора, SHA-256
ключа, SHA-256 SID, текущего старого срока, наблюдаемого HTTP 200/204
и фиксированного метода
`POST https://finance-api.wildberries.ru/api/finance/v1/sales-reports/detailed`.
Время исходного запроса плюс 12 часов обязано точно равняться старому
сроку. Время операторской проверки должно быть между запросом и текущим
временем; требуется ссылка на свидетельство успешной пробы.

Это операторское свидетельство, а не криптографическая квитанция WB.
Оно применимо только к независимо проверенному успешному запросу без
`Retry-After`. Исходный резерв архивируется до замены, а SHA-256 квитанции
сохраняется в новой версии журнала. Для квоты версии 2 повторная миграция
запрещена. Неизвестный срок, другой ключ или несовпадение реквизитов
означают отказ; удалять журнал для обхода этого отказа нельзя.
