# Дополнительные методы чтения WB и поиск Ozon

Базовое расширение добавило 15 инструментов WB и 2 инструмента Ozon.
С учётом отчёта остатков продавца и первого пакета операционных данных
в direct-режиме всего 114 инструментов Analytics MCP (WB 48, Ozon 49,
общие и PostgreSQL 17).
Это расширение перечисленных рабочих сценариев, а не реализация всего API
обеих площадок. Control MCP, задания сборщика и схема PostgreSQL этим
изменением не расширяются. `reporting_only` сохраняет 17 прежних инструментов.

## Каталог и контракты WB

| Инструмент | Официальный запрос | Назначение |
|---|---|---|
| `wb_reviews` | GET feedbacks-api `/api/v1/feedbacks` | Отзывы, обработка, SKU, Unix-даты, сортировка |
| `wb_review` | GET feedbacks-api `/api/v1/feedback?id=…` | Один отзыв |
| `wb_questions` | GET feedbacks-api `/api/v1/questions` | Вопросы, обработка, SKU, Unix-даты |
| `wb_question` | GET feedbacks-api `/api/v1/question?id=…` | Один вопрос |
| `wb_reviews_archive` | GET feedbacks-api `/api/v1/feedbacks/archive` | Архив отзывов |
| `wb_return_claims` | GET returns-api `/api/v1/claims` | Заявки покупателей на возврат, доступные за последние 14 дней |
| `wb_product_card_errors` | POST content-api `/content/v2/cards/error/list` | Ошибки создания/изменения карточек |
| `wb_product_card_limits` | GET content-api `/content/v2/cards/limits` | Лимиты карточек без покупки слотов |
| `wb_product_cards_trash` | POST content-api `/content/v2/get/cards/trash` | Карточки в корзине |
| `wb_subject_characteristics` | GET content-api `/content/v2/object/charcs/{subjectId}` | Официальные требования к характеристикам предмета |
| `wb_product_content_diagnostics` | POST content-api `/content/v2/get/cards/list` | Локальная проверка заполнения одной страницы карточек |
| `wb_supplies` | POST supplies-api `/api/v1/supplies` | Список поставок FBW с датами/статусами |
| `wb_supply` | GET supplies-api `/api/v1/supplies/{ID}` | Детали, склад и приёмка |
| `wb_supply_goods` | GET supplies-api `/api/v1/supplies/{ID}/goods` | Товары и количества |
| `wb_supply_packages` | GET supplies-api `/api/v1/supplies/{ID}/package` | Упаковка поставки |

Все имена хостов в таблице имеют фиксированный суффикс `.wildberries.ru`.
Фильтры большинства новых WB-инструментов находятся в `query`, селектор
кабинета — в корневом `account`. ID единичного отзыва/вопроса, `subject_id`
и `supply_id` упаковки также находятся в корне. Неизвестные поля запрещены,
положительные ID и границы проверяются сервером, не только JSON Schema.

Примеры аргументов:

```json
{"account":"allowed-account","query":{"is_answered":false,"limit":100,"offset":0,"order":"dateDesc"}}
```

```json
{"account":"allowed-account","query":{"is_archive":false,"nm_id":123,"limit":100,"offset":0}}
```

```json
{"account":"allowed-account","query":{"dates":[{"from":"2026-09-01","till":"2026-09-07","type":"factDate"}],"status_ids":[5,6],"limit":100,"offset":0}}
```

Каждый вызов возвращает одну страницу, а не полный отчёт:

- Отзывы/вопросы/архив: локальный `limit` 1–100. Отзывы и архив: `offset`
  до 199990. Вопросы: `limit + offset <= 10000`; большие периоды разделяйте
  по датам. Параметры передаются как `take`, `skip`, `nmId`, `dateFrom`, `dateTo`.
- Заявки: `limit` 1–200, `offset` до 1000000. Архив выбирается явно через
  `is_archive`. Показатели из продаж и финансовых отчётов потребуются для
  полной истории возвратов; этот инструмент её не заменяет.
- Ошибки карточек: `limit` 1–100; продолжение парой `updated_at` + `batch_uuid`
  из ответа. Завершение по `cursor.next=false`. Это актуальный POST, не старый GET.
- Корзина: `limit` 1–100; продолжение парой `trashed_at` + `nm_id`; сохраняйте
  оригинальный курсор, завершайте по документированному `total < limit`.
- Поставки/товары: `limit` 1–1000, `offset` до 1000000; пустая/короткая страница
  завершает проход. Это поставки FBW на склад, не сборочные задания FBS.
  Для деталей и товаров `is_preorder_id=true` выбирает ID предварительного
  заказа. Метод упаковки принимает только ID поставки.

Диагностика возвращает `coverage=single_page`, оригинальный `cursor`,
`checked_count`, проверки заполнения и известные пропуски `findings`.
`null` означает N/D; пустое поле — `false`; заполненное — `true`.
Это не проверка модерации и не доказательство выполнения всех требований
категории: для этого сопоставьте требования предмета и ошибки карточек.

## Поисковая аналитика Ozon

- `ozon_search_product_queries`: POST `/v1/analytics/product-queries`.
- `ozon_search_product_query_details`: POST `/v1/analytics/product-queries/details`.

Первый принимает `store`, `date_from`, необязательный `date_to`, `skus`,
`page`, `page_size`. Второй принимает те же корневые поля и отдельный
`limit_by_sku` (1–1000). Даты — RFC3339; SKU — уникальные положительные
десятичные строки (1–1000 штук); `page` 0–10000, `page_size` 1–1000
(по умолчанию 100). Интервал с `date_to` ограничен локально 31 сутками.

```json
{"store":"allowed-store","date_from":"2026-09-01T00:00:00Z","date_to":"2026-09-07T23:59:59Z","skus":["123"],"page":0,"page_size":100}
```

Ответ и сведения о страницах сохраняются без подмены отсутствующих метрик
нулём. Для недельной истории старше месяца передавайте `date_from` без
`date_to`; доступность и глубину определяет подписка Ozon. Это аналитика поисковых
запросов; для статистики рекламных кампаний нужны рекламные методы. Уровень Premium и фактические права
ключей этим изменением не проверены живыми запросами.

## Доступ, квоты и данные

Каждый вызов повторно проверяет личность и доступ к кабинету. Клиенты
разрешают только фиксированные пары HTTP-метод/путь на заданном хосте.
POST для отчётного чтения разрешён; соседние операции ответа покупателю,
изменения карточек, приёмки возвратов и создания поставок не разрешаются.

Используются существующие таймауты, предел ответа 2 MiB, запрет перенаправлений,
локальная квота и общая PostgreSQL-квота, если она настроена. Новый поиск Ozon
имеет отдельную от продаж квоту 65 секунд на Client-Id и не использует кеш
`/v1/analytics/data`. Ошибки поиска не повторяются автоматически; локальный
cooldown учитывает Retry-After с пределом 24 часа, исходный заголовок
передаётся в общую квоту и сообщение об ошибке.

WB-квоты намеренно консервативны до отдельной проверки типа ключа и доступа:
все отзывы/вопросы вместе — 720 секунд, заявки на возврат — 3600 секунд,
поставки FBW вместе — локальный предел 3600 секунд, ошибки карточек — 6 секунд.
Это выбранные ограничения MCP, не утверждение о максимальной скорости
каждого типа токена WB. Остальные чтения контента используют существующую
квоту. Новые группы не повторяют ошибки автоматически. При локальной паузе
инструмент возвращает время ожидания, а не держит сетевое соединение час.

Категории ключа WB: «Отзывы и вопросы», «Возвраты покупателей», «Контент»,
«Поставки». Наличие категории не доказывает текущую авторизацию. HTTP
401/402/403/429 остаются ошибками, а не пустыми данными. Ключи не передаются
в модель; инструмент не принимает URL, HTTP-метод или произвольное тело.

Структурированные телефоны, контакты, `userName`, `user_name`, `lastOrderShkId`
и остальные ранее защищённые персональные поля редактируются. Свободный текст
отзыва может сам содержать персональные сведения: его полная автоматическая
анонимизация не заявляется. Текст и ссылки помечаются недоверенными данными;
вложения и ссылки из ответа не скачиваются.

## Источники контрактов

Проверены официальные описания и примеры запросов 13 сентября 2026 года.
Часть WB-параметров доступна через индексированные выдержки; зеркало `.cn`
использовано для формы запросов общения с покупателями. Адреса API этого
сервера остаются `.ru`; тарифы и ключи каждого кабинета проверяются отдельно.

- [WB: общение с покупателями](https://dev.wildberries.ru/openapi/user-communication)
  и [официальное зеркало описаний](https://dev.wildberries.cn/docs/openapi/customer-communication).
- [WB: карточки](https://dev.wildberries.ru/openapi/work-with-products).
- [WB: поставки FBW](https://dev.wildberries.ru/openapi/orders-fbw).
- [Ozon: объявление поисковых методов](https://dev.ozon.ru/news/512-Novye-metody-dlia-raboty-s-analitikoi-po-zaprosam-tovarov-v-Seller-API/).
- [Ozon: параметры детализации](https://docs.ozon.ru/api/seller/#operation/AnalyticsAPI_AnalyticsProductQueriesDetails)
  — прочитаны в браузере, HTTP-выгрузка документации была недоступна.

Контрактные тесты используют синтетические ответы и проверяют маршрутизацию,
пагинацию, ошибки, RBAC, отсутствие записи, редактирование персональных полей,
N/D, локальное ограничение поиска и исключение прямых методов из reporting_only.
Это не подтверждение живой доступности всех методов для производственных ключей.
