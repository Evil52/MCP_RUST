Ключи не выводились и не записывались в отчёт; новые ключи не подключались.
Ни один метод изменения магазина не использовался. Статус конфигурации
кабинета сам по себе не использовался как доказательство доступа.

Для `ofk` дополнительно успешно вызван `/v1/finance/accrual/types`:
124 записи справочника. В проверенных 442 начислениях `accrual_id` уникален

компонентах: `item_fees`, `non_item_fee`, деталях `posting`.
Исправление первого этапа обосновано: ID начисления нельзя использовать как
ID типа услуги. Сумма `total_amount` содержит точную строку `amount` и валюту;
добавление компонентов к этой же общей сумме привело бы к двойному счёту.

Эти ответы не подтверждают отсутствие прав записи у Ozon-ключа, доступ ко
всем финансовым методам или условиям Premium/других подписок. Список ролей
ключа Ozon в этом тесте не получен; соответствующий статус — N/D.

## WB: локальные сведения и ответ действующего API

Проверен каталог ключей, фактически смонтированный в работающий
`report-collector`, без вывода самих токенов, их ID и идентификаторов продавца.
У всех семи кабинетов (`ofk_region_wb`, `ip_usovik_wb`, `ofk_komplekt_wb`,
`ip_teterevenkov_wb`, `ip_sinelshchikov_wb`, `ip_domnyshev_wb`, `ip_voronin_wb`)
в payload JWT указаны `acc=3`, бит 30 «только чтение» и бит 13 «Финансы»;
срок истечения — 29 января 2027 UTC.

Значения прочитаны локально, подпись JWT не проверялась. Такая расшифровка
не доказывает, что токен не отозван или что конкретный метод доступен.
WB описывает поля и рекомендует проверять фактический статус через API:
[официальная документация токенов](https://dev.wildberries.ru/docs/openapi/api-information),
[декодирование и проверка](https://dev.wildberries.ru/knowledge-base/articles/019d49a1-1540-76f6-befe-726633dc11be/dekodirovanie-i-proverka-tokenov-wb-api).

Затем новый Rust `finance-collector probe-wb` выполнил по одному запросу
`POST /api/finance/v1/sales-reports/detailed` за 2026-09-12 для каждого из
этих семи кабинетов. Везде получен **HTTP 200** с текущими ключами чтения.
Использованы `period=daily`, фиксированная проекция и `limit=1`; строки
финансов не выводились и не сохранялись. Следовательно, этот конкретный
метод работает с имеющимися Personal read-only ключами категории Finance;
переход на ключи с записью для проверенного метода не требуется.

Отдельно проверена привязка продавца. В действующем реестре `seller_sid`
заполнен только для `ofk_region_wb` и `ip_domnyshev_wb` и совпадает с ключами
сборщика. Для остальных пяти кабинетов независимая привязка SID отсутствует.
Пробные HTTP 200 подтверждают доступ установленных ключей к методу, но не
заменяют эту проверку соответствия кабинету. Перед постоянным сбором нужно
подтвердить продавца по доверенным данным кабинета и закрепить его SID.
Автоматически копировать SID из непроверенного ключа в реестр нельзя.

После независимой проверки кода `finance-collector` усилен: отсутствие SID
или несовпадение блокирует запрос и публикацию. Первые пробы выполнены до
введения обязательной привязки; повторных запросов после усиления не было.
Боевые реестры не изменялись. Поэтому новый сборщик пока допустит только
два кабинета с уже подтверждённой привязкой, даже если остальные ключи
имеют правильные Finance/RO-права.

Запросы выполнены 13 сентября примерно в 11:07–11:08 UTC. Они не проверяют
полноту отчётов: везде `pagination_complete=false`. Не проверялись другие
Finance-методы, права сервисных/базовых ключей или условия подписок.
После этих проб резерв квоты был сохранён до 23:07–23:08 UTC в закрытом локальном каталоге
`/private/tmp/ofk-finance-probe-20260913`; каталог не следует удалять ради
повторного вызова. Он содержит только хешированную область продавца и
время следующего запроса; на момент проб финансовых строк в нём не было. Все запуски
постоянного сборщика должны использовать один deployment-owned state-dir.

Без ключа выполнен HTTPS-запрос к фиксированному финансовому домену WB:
TLS-проверка успешна, получен ожидаемый 401. Этот запрос проверяет сетевую
доступность, но не права ключа. Сетевые маршруты и действующие egress ACL не
менялись. В исходный конфиг прокси добавлен только домен нового метода;
его разрешение HTTP-операций внутри TLS по-прежнему обеспечивает Rust.
