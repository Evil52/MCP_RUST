## Реализация

Read-only инструменты ozon_clusters, ozon_cluster_stock_analytics,
ozon_supply_bundle имеют фиксированные пути, ограниченные ID/размеры запросов
и сохраняют доступ только к разрешённому кабинету. При has_next=true состав
поставки нужно дочитать с last_id, не меняя исходные фильтры.

Ozon возвращает знаковые int64 ID складов, включая отрицательные ID с реальными
остатками. Идентификатор сохраняется без изменения в API-фильтрах, warehouse
stock dimensions и кластерных снимках. Миграция 057 разрешает ненулевые
знаковые warehouse_id; NULL остаётся неизвестной парой, нулевой ID запрещён.
Один warehouse_id может встречаться в разных кластерах. Миграция 058 и
нормализатор сохраняют отдельную строку для каждого сочетания SKU, склада,
cluster_id и macrolocal_cluster_id. Точные дубликаты этого сочетания запрещены;
пагинация reader использует все координаты для стабильного порядка строк.

Для reporting-only добавлены независимые опубликованные источники
ofk_source_snapshot(source=cluster_stocks) и source=posting_movement.
REPORT_COLLECTION_REPLENISHMENT_ENABLED=true включает их отдельно после
миграций 055/056 и проверки reader/collector. По умолчанию выключен; выключение
также запрещает захват уже созданных дополнительных заданий. Очередь отдаёт
приоритет обязательным KPI-источникам. Дополнительные источники не меняют
полноту ежедневного отчёта и не хранят контакты покупателей.
При временных HTTP 5xx кластерного источника и явно заданном сроке cooldown
паузы составляют 5, 10, 20, 40 и 80 секунд. `Retry-After` и общая квота могут
увеличить паузу. Для 429 без срока ожидания, остальных источников и окна
свежести 30 минут сохраняются прежние правила. Журнал содержит выбранную
паузу и переданный срок ожидания без тела ответа или реквизитов доступа.

Cluster stocks покрывает перечисленные product/info/stocks SKU, а не весь
каталог или все пары SKU/кластер. Отсутствие строки не означает нулевой запас.
Если запрошенный SKU вообще не возвращён, сохраняется неизвестная строка без
счётчиков и снимок partial. catalog_scope=listed_fulfillment_skus, coverage
считается по всему снимку, время наблюдения возвращается явно.

## Правила планирования

900 — максимум, не обязательное заполнение. Ненулевая партия SKU/кластер —
от 5 шт.; максимум 60 строк суммарно по двум кластерам. Показывать отдельно
число уникальных SKU; один SKU может быть нужен обоим кластерам.
Распределение 450/450 не следует из ограничений.

ads_cluster — среднесуточный спрос с периодом, определяемым Ozon. Метод не
принимает даты: нельзя представлять показатель как продажи именно 01–14.10.
Одинаковый ads_cluster повторяется по складам одного SKU/кластера, его нельзя
суммировать. Не суммировать повторяющиеся incoming/requested без подтверждения
гранулярности. Количества в пути не подтверждают дату приёмки; позиции заявок
и транзитные счётчики могут описывать одни единицы — не вычитать их дважды.
Склад отправления не является автоматически кластером покупателя.

По указанию пользователя себестоимость не подключается, прибыль недоступна.
Ранжирование по GMV или скорости спроса не выдавать за максимизацию прибыли.
Живые поставки этим исправлением не создаются.

## Применение и возврат версии

Штатный immutable release workflow: проверенная CI-сборка, миграции,
canary/readback и только затем включение дополнительных источников.
Секреты остаются на Ubuntu. После публикации новых источников старый reader
может не распознать значения source. Для отката сначала выключить
дополнительный сбор и проверить совместимость reader или restore-план;
не удалять опубликованные факты ради возврата версии.
