# Восстановление неподтверждённой ставки Nexus

Миграция `041_wb_nexus_incident_recovery.sql` добавляет операторскую функцию
`wb_automation.recover_nexus_unconfirmed_bid`. Её исполнение не отправляет
запрос на WB. Обычный робот доступа к функции не имеет. Установка миграции
сама по себе не снимает инцидент.

Применять только после явного разрешения сохранить **текущие ставки** Nexus,
закрыть конкретную неподтверждённую попытку как `cancelled` и восстановить
автоматическое управление кампанией. Результат старой записи останется
неизвестным; повторять её нельзя.

Перед вызовом проверить опубликованный выпуск БД, резервную копию и свежий
независимый readback WB. Функция дополнительно требует точную кампанию
`ofk_region_wb` / `40141836`, пять согласованных товаров, статус 9, полный
дневной расход ниже 450 ₽, положительный остаток бюджета и ставку старого
запроса, которая **не видна** в readback. Цикл робота с теми же политикой и
ревизией должен быть не старше 90 секунд. Старый ключ попытки, ревизия,
политика и JSON всех текущих ставок передаются как типизированные параметры:

```sql
SELECT wb_automation.recover_nexus_unconfirmed_bid(
    $1, $2, $3, $4, $5::jsonb, $6
);
```

Для `$6` использовать ссылку на конкретное разрешение пользователя. После
ошибки или таймаута сначала перечитать состояние, попытку и audit; не вызывать
функцию повторно вслепую. Проверить также следующий плановый цикл робота и
новый readback WB. Снятие блокировки позволяет роботу снова выполнять
действия по действующей политике; это не ручная установка ставки.
