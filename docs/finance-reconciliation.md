# Сверка финансовых колонок WB

Проверка контракта: 13 сентября 2026 года. Модуль
`src/reporting/finance_reconciliation.rs` выполняет точное сравнение колонок
и не подключается к маркетплейсу. Ни ключи, ни сервисы, ни рабочая БД для
этой проверки не использовались.

## Что установлено по официальным источникам

В [документации WB](https://dev.wildberries.ru/docs/openapi/financial-reports-and-accounting)
и [официальном зеркале](https://dev.wildberries.cn/docs/openapi/documents-and-accounting)
описаны следующие операции чтения:

| Операция | Контракт |
| --- | --- |
| `POST /api/finance/v1/sales-reports/list` | Итоги по отчётам; `dateFrom`, `dateTo`, `period`, `limit` до 1 000, `offset`; история с 2025-01-01 |
| `POST /api/finance/v1/sales-reports/detailed/{reportId}` | Строки конкретного отчёта; `limit` до 100 000, `rrdId`, `fields`; следующая страница по последнему ID, завершение только HTTP 204; история с 2025-01-01 |

Оба метода заявлены для Personal/Service-токенов категории Finance.
На зеркале присутствует предупреждение о недоступности в стране регистрации;
это не доказывает недоступность для российского кабинета. Российская страница
читалась через индексированные выдержки. Права конкретных ключей и подписки
этими источниками не подтверждены.

Список отдаёт отдельные показатели `retailAmountSum`, `forPaySum`,
`deliveryServiceSum`, `paidStorageSum`, `paidAcceptanceSum`, `deductionSum`,
`penaltySum`, `additionalPaymentSum`, три суммы кешбэка, `paymentSchedule`
и `bankPaymentSum`. Денежные значения представлены строками.

[Инструкция продавца WB](https://seller.wildberries.ru/instructions/ru/ru/material/how-to-read-fimancial-reports-detalization),
обновлённая 2026-08-27, объясняет, что тип документа обозначает направление
операции. Для некоторых услуг он пустой. При этом возвраты комиссий за кешбэк
и корректировки имеют собственную семантику. Поэтому одинаковое название
колонки и суффикс `Sum` недостаточны для проверенной формулы общего итога.

## Реализованные гарантии

- Каждая из 21 исходных денежных колонок складывается отдельно, в группах
  `report_id + currency`. Выплата, оборот и комиссия не складываются вместе.
- Коэффициенты сумм — checked `i128`, масштаб сохраняется до 18 знаков.
  В JSON коэффициент передаётся строкой; сравнение не использует `f64`,
  округление до копеек или допуск. Разница в одну миллиардную выявляется.
- Если хотя бы в одной строке сумма отсутствует, итог этой колонки недоступен.
  Сохраняются количества присутствующих и отсутствующих значений. Пустая
  выборка не создаёт отчёт с нулевым балансом.
- Повторный `rrd_id`, неверная нормализованная строка и превышение ограничения
  25 000 строк отклоняются. Положительная сумма возврата остаётся положительной
  исходной суммой. Неизвестные типы документов учитываются отдельно.
- Для сравнения нужны одинаковые кабинет, ID отчёта, валюта, периодичность и
  границы отчёта; у обоих источников — подтверждение завершения и полного
  покрытия отчёта. HTTP 204 по одному дню не подтверждает целую неделю.
- Независимый эталон содержит ID наблюдения, SHA-256 сохранённого свидетельства
  и точные суммы явно выбранных колонок. Совпадающий ID наблюдения или хеш
  свидетельства не принимается за независимую проверку. Свидетельство должно
  включать происхождение выгрузки, а не только скопированные значения.
- Проверяются отсутствующие/неполные эталоны, неверные границы, повреждённые
  агрегаты и переполнение при приведении масштабов.

Функция `reconcile_wb_finance_report` возвращает `raw_columns_match`,
`mismatch` или `unavailable`. Первый статус означает совпадение только
перечисленных колонок с независимым эталоном. Он не означает подтверждение
прибыли, банковской выплаты или полной сверки финансового отчёта.

Эталон с типом `official_report_summary` всегда получает
`unverified_official_summary_mapping`. Это намеренное ограничение до проверки
знаков и формул на обезличенном полном отчёте, его детализации и независимых
итогах. Модуль не предоставляет состояние `reconciled`.

## Отдельная сверка официальной сводки

`wb_report_source` и `wb_official_reconciliation` добавляют независимую
загрузку `/list` и `/detailed/{reportId}`, завершение обеих выгрузок HTTP 204
и проверенные правила для `retailAmountSum` и `forPaySum`. Вызовы имеют
отдельные точные разрешения в клиенте; CLI проверяет оператора, кабинет и
ключ. [Контракт формул](wb-official-reconciliation.md) сохраняет знаки
возвратов и корректировок. [Живой пилот](finance-canary-20260913.md)
подтвердил оба итога на полном отчёте ОФК.

Общий raw-модуль выше по-прежнему не выдаёт официальную сводку за сумму
сырых колонок. Новая официальная проверка доступна отдельно через
[`ofk_wb_report_reconciliation`](wb-report-mcp.md). Остальные удержания,
банковская выплата и прибыль требуют своих правил. Хеш не заменяет
подлинность источника или проверку прав пользователя.

## Проверка

Синтетические тесты охватывают раздельные валюты/отчёты, большие ID и суммы,
точность JSON, возвраты и неизвестные документы, отсутствующие суммы,
повторные строки, неполное покрытие, несовпадение кабинета/периода,
неразличимые свидетельства, неподтверждённую сводную формулу и расхождения.
Команда: `cargo test --offline --locked --lib reporting::finance_reconciliation::tests`.

## Чтение журнала через MCP

Добавлен `ofk_wb_financial_ledger`. Он читает опубликованные проекции PostgreSQL
через существующее ограниченное соединение `ReportingReader`, включая режим
`reporting_only`. При каждом вызове сервер заново проверяет сотрудника,
разрешённый кабинет WB и роль `finance`/`admin`; затем проверяет контракт роли БД.
Ключей маркетплейса, универсальных путей и выбора полей в этом инструменте нет.

Первый запрос: `{"account":"wb-account","limit":100}`. Следующая страница
передаёт возвращённые `batch_id` и `next_after_rrd_id` как `after_rrd_id`;
выбранный пакет остаётся неизменным. Курсор — строка, чтобы не потерять точность
большого WB ID. Размер страницы ограничен 1 000 строками, дополнительная строка
определяет наличие следующей страницы и не выдаётся пользователю.

Ответ содержит происхождение пакета, период, количество строк, время публикации
и HTTP-статус завершения источника. ID строк, отчётов и SKU, а также коэффициенты
денежных сумм представлены строками. При отсутствии пакета — `state: "N/D"`
и `batch: null`; полный пустой пакет имеет `state: "COMPLETE"` и
`row_count: 0`. `reconciliation_state` пока всегда `N/D`: публикация после
последней страницы не равна независимой финансовой сверке.
