# Раздельная маршрутизация MCP на macOS

WB/Ozon должны выходить через локальный Ethernet/Wi-Fi-шлюз, а OpenAI — через
VPN. Проверка 9 сентября 2026 года подтвердила эту схему на текущем Mac:
`en0` (Ethernet), шлюз `192.168.0.1`, OpenAI через `utun4`. API-ключи прежние,
проверка сертификатов HTTPS включена. Это отдельная настройка хоста, не изменение
Rust-клиентов, разрешений кабинетов или read-only egress-прокси коллектора.

## Что проверено до установки

- В 13:38 Екатеринбурга через OFK MARKET получены 25 карточек
  `ip_domnyshev_wb`; в 13:39 — страница текущих остатков Ozon
  `furnitura_dlya_doma` с `limit=1`.
- В 13:45 новый `marketplace_routes.py check --probe` проверил все 9 доменов
  маркетплейсов и каждый их текущий IPv4. WB ответил за 0,62–0,66 с,
  Ozon — за 0,11–0,12 с, OpenAI — за 0,34–0,37 с.
- Неавторизованный запрос `/v1/models` OpenAI вернул ожидаемый 401 через VPN.
  MCP `/healthz`, `/readyz` и последняя успешная команда poll прошли проверку;
  возраст poll составил 28 с при допустимых 90 с.
- HTTP 401 WB, 403 корня Seller API Ozon и 404 корня Performance API в этой
  проверке подтверждают только TLS/HTTP-транспорт. Ключи в эти пробы не передаются.
  Чтение бизнес-данных подтверждено отдельно указанными выше MCP-вызовами.
- На момент проверки разделение обеспечивали уже существующие маршруты.
  Новый root LaunchDaemon **не установлен**: `sudo -n` требует пароль.
  Реальные add/delete маршрутов, перезагрузка Mac и переподключение VPN
  с новым daemon пока **не проверены**. Сценарии восстановления/отката проверены
  на модели маршрутов; это не заменяет приёмку установленной настройки.
- Итоговая проверка в 13:54: 11 доменов (9 marketplace + 2 VPN), 13 HTTPS-проб,
  возраст MCP poll 18 с. В 13:55 получена следующая cursor-страница WB из
  25 карточек и 25/25 запрошенных размеров склада ФБС МГТ (`1349449`), без
  `missing_chrt_ids`. Это проверка одного пакета, не полного каталога.
- На macOS с системным Python 3.9.6 прошли 24 теста маршрутизации, ShellCheck,
  `bash -n`, `plutil -lint` и `git diff --check`. Тесты добавлены в Rust CI;
  удалённый CI для этой ветки пока не запускался.

## Политика

Фиксированный список совпадает с API-хостами текущих клиентов:

| Направление | Домены |
| --- | --- |
| Напрямую | `api-seller.ozon.ru`, `api-performance.ozon.ru` |
| Напрямую | `seller-analytics-api.wildberries.ru`, `statistics-api.wildberries.ru`, `content-api.wildberries.ru`, `discounts-prices-api.wildberries.ru`, `common-api.wildberries.ru`, `advert-api.wildberries.ru`, `marketplace-api.wildberries.ru` |
| Проверять VPN | `api.openai.com`, `chatgpt.com` |

`apply` разрешает DNS заново и при необходимости добавляет только IPv4 `/32`
через явно выбранный локальный шлюз. Работающие маршруты провайдера не
перезаписываются и не присваиваются скрипту. Собственные правила отмечаются
`STATIC/PROTO2` и записываются в root-журнал до добавления; после операции
проверяется фактический маршрут. Старые DNS-адреса удаляются только из собственных
правил. При неудачном добавлении откатываются правила текущей попытки.

Явный чужой host route не заменяется. Маршруты, заменённые другим владельцем,
при rollback сохраняются. macOS `HOST/WASCLONED` учитывается как кэш маршрута,
а не ручной host route. DNS-сбой, непубличный адрес, пересечение с OpenAI,
отсутствующий VPN или недоступный локальный шлюз останавливают новые изменения.

Список хостов не настраивается из окружения. Скрипт не меняет default route,
VPN, DNS-сервер, firewall, TLS, Docker-сети, egress ACL, ключи или расписание
сбора. Существующий `.no_proxy()` остаётся включённым: он исключает ambient
HTTP-прокси, но не управляет VPN-маршрутами ОС.

## Проверка без изменений

Из корня этой ветки:

```bash
/usr/bin/python3 -B scripts/marketplace_routes.py plan \
  --config ops/macos/marketplace-routing.example.json

/usr/bin/python3 -B scripts/marketplace_routes.py check \
  --config ops/macos/marketplace-routing.example.json --probe \
  --tunnel-url-file "$HOME/Library/Application Support/tunnel-client/health/ozon-local.url"
```

`plan` ничего не меняет. Пустой `add` означает, что исключения уже действуют.
`check --probe` проверяет маршрут всех адресов, HTTPS с обычной проверкой
сертификата и повторный маршрут после проб. Файл URL ограничен loopback через
существующий `operations_heartbeat.probe`. Только полный вызов с
`--tunnel-url-file` подтверждает также свежесть MCP poll.

Пример конфигурации соответствует проверенному Mac. На другом хосте сначала
уточнить устройство через `networksetup -listallhardwareports` и шлюз через
`route -n get default`. Номер `en0` не означает Wi-Fi; в проверенном окружении
это Ethernet. Не переносить IP шлюза с Mac на Ubuntu автоматически.

## Установка и приёмка

После просмотра diff и успешного check выполнить **в этой ветке**:

```bash
sudo bash scripts/install-marketplace-routing.sh install \
  ops/macos/marketplace-routing.example.json \
  "$HOME/Library/Application Support/tunnel-client/health/ozon-local.url"
```

Установщик до и после первого apply требует работающие маршруты, HTTPS и свежий
MCP poll. Он размещает копии кода
и конфигурации в защищённом root-каталоге
`/Library/Application Support/MCP_OZON/marketplace-routing`, журнал — в
`/private/var/db/mcp-ozon-marketplace-routing`, а plist — в
`/Library/LaunchDaemons/com.ofk.mcp-ozon-marketplace-routing.plist`.
Используется системный Python 3.9+ `/usr/bin/python3 -I -B`; writable Homebrew
интерпретатор и код из рабочего каталога daemon не исполняет.

Daemon выполняется при загрузке и раз в 60 с, с kernel lock и общим дедлайном.
При текущих корректных маршрутах первый `apply` не добавляет правил.
После установки:

1. Повторить полный `check --probe --tunnel-url-file ...`.
2. При наличии локального доступа переподключить VPN, дождаться следующего
   прохода daemon и повторить полный check. Не проводить такой опыт на
   единственном удалённом канале доступа.
3. Прочитать карточки WB с переходом курсора, перечень FBS-складов и остатки
   ограниченного пакета `chrtID`; отдельно прочитать текущие остатки Ozon.
   Убедиться в успешных серверных вызовах, а не только в HTTP 401 ping.
4. Проверить то же после согласованной перезагрузки Mac.

До этих шагов автоматическое восстановление после reconnect/reboot не считать
подтверждённым. Сам `launchctl bootstrap` также не доказывает успешный проход.

## Откат и ограничения

```bash
sudo bash scripts/install-marketplace-routing.sh uninstall
```

Откат сначала останавливает daemon и удаляет только журналированные host routes
с совпадающими маркером и шлюзом. Если удаление не удалось, журнал сохраняется
для повторной попытки. Код и логи остаются для диагностики. Перед сменой
интерфейса/шлюза сначала выполнить откат со старой конфигурацией.

- Это периодическое восстановление маршрутов, не firewall: между изменением
  сети и очередным проходом возможен интервал до 60 с плюс время проверки.
  Во время такого перехода существующие соединения могут оборваться.
- Правило действует на IP для всего Mac, не только на процесс MCP. Совместный
  IP других сайтов тоже получит прямой маршрут. HTTPS и API-права сохраняются.
- Политика пока только IPv4. Если DNS выдаёт AAAA, скрипт завершится ошибкой,
  а не объявит обход полным и не отключит IPv6 глобально.
- VPN kill switch/Network Extension может блокировать соединение независимо
  от таблицы маршрутов. Защиту скрипт не отключает: нужен успешный HTTPS-check.
- Daemon не включает VPN и не переводит OpenAI на прямой доступ при его сбое.
  Полный check и штатные проверки MCP нужны дополнительно к журналу daemon.
- FBS/FBW, `missing_chrt_ids` и полнота исторических снимков остаются отдельными
  контрактами. Стабильный маршрут не создаёт недостающие исторические данные.
- Для Ubuntu нужен отдельный Linux deployment с проверкой Docker egress и
  SSH-доступа; этот macOS daemon туда не устанавливается.

Встроенный режим Red Shield [Local Sites Without VPN](https://redshieldvpn.com/en/faq)
можно сохранять включённым; результат определяется маршрутом и реальным HTTPS,
а не только положением переключателя. Синтаксис и маркеры маршрутов сверены с
локальным macOS `man 8 route`.
