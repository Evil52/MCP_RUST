# Операторский сбор финансового журнала WB

`finance-collector` — отдельный Rust-бинарник для явных локальных запусков.
Установка не включает расписание. Он не предоставляется как MCP-инструмент:
`--actor` — идентификатор доверенного оператора ОС, а не удалённая
аутентификация. Запуск из веб-обработчика с присланным клиентом actor запрещён.
Для менеджеров используется JWT-проверка существующего MCP и новый
`ofk_wb_financial_ledger`, который читает только PostgreSQL.

## Подготовка

- Проверенная миграция `032_financial_ledger.sql` в отдельной целевой БД.
  В этой работе миграции применялись только в одноразовых тестовых БД.
- Реестр доступа, разрешающий оператору finance/admin конкретный кабинет WB,
  и обязательный `wildberries.seller_sid`, независимо подтверждённый для
  продавца. SID обязан совпадать с ключом; подмена имени файла недостаточна.
- Приватный каталог ключей (0700), один нужный ключ по имени из реестра
  (0600 или строже): Personal, только чтение, Finance, не истёкший.
  Расшифровка JWT — предварительная проверка; настоящий ответ API отдельно
  подтверждает доступ. В command line и логах ключей нет.
- Один защищённый постоянный каталог состояния для всех запусков и периодов
  этого развёртывания. Не хранить рабочую квоту в очищаемом временном каталоге.
- Для публикации — отдельный `REPORT_COLLECTOR_DATABASE_URL` с ролью
  `report_collector`. Проверяется узкая функция публикации; прямой доступ
  к таблицам журнала запрещён. MCP использует reader, импорт 1С — свою роль.

## Явные команды

После сборки `cargo build --locked --bin finance-collector`:

```sh
finance-collector probe-wb \
  --registry /etc/mcp-ozon/access.json \
  --actor finance_operator --account wb_pilot \
  --credentials-dir /run/mcp-ozon/report-credentials \
  --state-dir /var/lib/ofk-finance \
  --from 2026-09-12 --to 2026-09-12 \
  --egress collector-proxy
```

Пример требует подготовленных путей и реальных разрешений; это не команда
для немедленного запуска продакшена. Для сбора заменяется только `probe-wb`
на `collect-wb`; URL БД передаётся через защищённую конфигурацию процесса.
Проба использует одну строку и выводит только метаданные результата. Её
данные не являются checkpoints полной выгрузки.

`collector-proxy` — фиксированный `http://ozon-egress:3128` внутри сети
сборщика, без произвольного proxy URL. `direct` использует обычный системный
маршрут к фиксированному HTTPS-домену WB и не изменяет VPN/DNS/маршруты.
Автоматического перехода между маршрутами нет. Прокси разрешает CONNECT к
домену; точные HTTP-метод/путь, проекцию и запрет redirect проверяет Rust.

## Продолжение и целостность

Перед HTTP сохраняется резерв квоты продавца на 12 часов; `Retry-After`
может только продлить паузу. Файл и каталог синхронизируются, каталоги —
вместе с родителем. Блокировка действует на всё выполнение. Это защита
одного хоста и общего каталога, не распределённая квота или гарантия
работоспособности неисправного хранилища. Удаление/смена каталога оператором
обходит эту границу; рабочий каталог должен принадлежать развёртыванию.

Ответ `deferred` означает, что нужно повторить ту же команду после
`next_request_at`. Неполная выгрузка не публикуется. Сохраняются только
проверенные нормализованные страницы, без raw JSON или ПДн. Каждый новый
HTTP-запрос и публикация заново проверяют роль, кабинет, SID и неизменность
привязки/ключа. Квота общая даже при разных периодах и алиасах одного SID.

Период — до 31 закрытого дня с 2024-01-29, страница — до 1000 строк,
выгрузка — до 25000 строк. Короткая страница не завершает сбор; требуется
HTTP 204. Публикация всех строк и сумм атомарна. Точный повтор возвращает
прежний пакет; изменение содержимого или пересечение source row ID с
другим пакетом даёт конфликт. История автоматически не переписывается.

Полный обход страниц не гарантирует единый момент состояния изменяемого
отчёта WB, особенно при длительном сборе. Журнал содержит время публикации
и исходные точные суммы; независимая финансовая сверка остаётся отдельной
проверкой. Суммы колонок пересекаются, отсутствующие значения — N/D.
Наличие пакета не подтверждает прибыль или совпадение с выплатой.
